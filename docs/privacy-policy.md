# 隐私政策草案

本文档用于当前校园综合服务 App 试点版本的隐私合规起草，不等同于最终法务版本。正式上线前必须由学校、法务和安全团队复核。

## 当前收集的数据

- 登录账号、身份类型、角色和基础资料。
- 本地会话令牌与会话过期时间。
- 代取、报修、失物招领、快递、钱包、公告、教师审批等业务数据。
- 管理员公告发布、会话清退和关键业务操作的审计记录。
- 本地 API 请求指标、失败状态和脱敏告警字段。

## 当前存储方式

- 前端使用浏览器 `localStorage` 保存会话、最近身份和快递比价表单。
- 后端开发模式可使用 [server/data/db.json](../server/data/db.json) 保存本地演示数据。
- 试点模式应使用 SQLite，默认文件为 `server/data/campus.sqlite`，并通过 migration、seed、backup、restore 脚本管理。
- 请求日志、指标和告警不应写入密码、token、请求体或敏感 query 参数。
- 备份默认写入 `server/backups`，该目录不进入 git，真实备份文件应按学校数据保留策略管理。

## 当前限制

- 学校统一认证、短信、支付、真实物流和外部监控仍未接入。
- SQLite 适合单机试点；多实例或正式生产应切换到受管数据库，并补齐集中备份、恢复演练和权限审计。
- 当前尚未实现用户自助导出、更正、删除和注销流程。
- 试点前需要确认真实域名、HTTPS、Android 签名证书、第三方 SDK 清单和数据出境情况。

## 上线前必须补齐

- 正式用户协议与隐私政策页面。
- 数据分类分级、保留周期、删除策略和备份销毁策略。
- 敏感字段加密、最小权限、管理员操作复核和审计检索。
- 第三方 SDK、学校统一认证、短信、支付、告警服务的数据共享清单。
- 用户查询、更正、删除、注销和投诉处理流程。
- 安全审计、渗透测试和合规评审记录。
